# Criterion skeptic report: sun-8-3 (p2)

Scope of this review: the enumerated partial win p2 only. The full success criterion (a family with rate |F|^(1/n) above 1.5545) is NOT claimed and NOT met by an (8,3) family (12^(1/8) is about 1.36); nothing is claimed about other (n,r) or the rate bar.

All files in claim.SHA256SUMS were checked with shasum -a 256 -c: every line OK.

## p2 clauses (quoted) and verdicts

p2 (CLAIM.md): "An exact value of g(n, r) ... for some (n, r) not previously published: an explicit family of size g plus a DRAT/LRAT-checked UNSAT proof that size g+1 is impossible, with the CNF regenerated by the verifier." (novelty is another skeptic's job)

1. "an explicit family of size g": MET. My own code (written before reading the author's) parsed the family file: n=8, r=3, 12 sets, all distinct, all 3 distinct points in 1..8. Brute force over all C(12,3)=220 triples with the definition A&B == A&C == B&C (so empty core counts): result OK, no sunflower. Negative controls rejected by the same code: repeated member -> "repeat"; three pairwise disjoint 3-sets in n=9 -> "sunflower"; {123,124,125} -> "sunflower"; {123,145,167} -> "sunflower". A random point permutation (4,1,2,5,7,3,6,8) of the family stays distinct, size 12, sunflower-free. Greedy random maximal-family search (3000 runs) never exceeded 12 (consistent, not a proof).

2. CNF content (plain CNF): MET. nosb.cnf has 56 'c var' lines, ids 1..56, whose subsets are exactly all C(8,3)=56 triples. Brute-force recomputation gives 1400 sunflower triples; the all-negative ternary clauses on set variables number 1400, all distinct, and equal exactly the brute-force set. The remaining 1088 clauses contain none that use only set variables (all involve auxiliaries). Cardinality test with my own DPLL/unit-propagation solver on those 1088 clauses: fixing exactly 11 random set variables true: consistent 0 of 60; exactly 12: 0 of 60; exactly 13: 60 of 60; exactly 14: 60 of 60. So they encode "at least 13 true". With the full plain CNF, the shipped 12-family fixed (others false) is UNSAT (needs 13), and the shipped family plus any one extra set is inconsistent in all 44 cases. The CNF forbids only 3-sunflowers (including empty-core) and the count bound; nothing else.

3. Symmetry-broken (proved) CNF: MET. subset_check.py: plain clauses 2488, proved 4952, extra 2464, var maps equal, "SUBSET OK". My own analysis: no duplicates; extra clauses are 28 set-variable-only clauses (one per transposition of two points, 28 = C(8,2)) plus clauses over 812 fresh auxiliaries numbered 616..1427; none touch the plain auxiliaries 57..615 except as shared unchanged clauses. Soundness argument in CLAIM.md judged correct: sunflower-freeness and the count are invariant under S_8; lex-leader constraints for any subset of group elements (here all transpositions) are satisfied by the lex-least member of any orbit, so lex-leader-CNF SAT iff plain CNF SAT. Spot check: the lex-least image (over all 40320 permutations) of the shipped family satisfies x <= x.sigma for all 28 transpositions, size 12, sunflower-free.

4. "with the CNF regenerated by the verifier": MET WITH A DEFECT. Regenerated with gen_cnf.py 8 3 13 OUT --sb alltrans using the python-sat interpreter, python-sat version 1.9.dev15 (CLAIM pins >= 1.8). Not byte-identical: cmp reports a difference at char 86 line 1. Cause: the shipped generator writes a header comment ending "; deg<=none" and the shipped sb.cnf header lacks it. After removing line 1 the files are byte-identical (cmp clean, 4951 remaining lines) and identical sha-wise in all clause and variable-map lines. So the author's own run_checks.sh step 6 ("regenerated CNF is byte-identical") would report DIFFERS. This is a comment-line-only mismatch (stale shipped header), not a clause difference; the regenerated CNF also gets "s VERIFIED" against the shipped proof.

5. "a DRAT-checked UNSAT proof that size g+1 is impossible": MET. drat-trim.c compiled with cc -O2; output on object/sb.cnf and object/sb.drup: "s VERIFIED" (3875 of 4471 lemmas in core, 0 RAT lemmas in core, verification 0.07 s). Same "s VERIFIED" on the regenerated CNF. Negative controls: first 4000 lines of the proof -> "ERROR: no conflict", "s NOT VERIFIED"; empty proof -> same. Proof format: DRUP, plain clause lines each ending in 0 (9735 lines ending " 0", 5266 'd' deletion lines, final line "0"); drat-trim is the checker the bank names. Proof length is for the lex-leader CNF; plain-CNF proof (48 MB) is not shipped (declared in CLAIM.md, not relied on).

6. Hidden quantifiers: none found. "3-sunflower" means the same thing in the bank statement (no three distinct sets with pairwise equal intersections, empty core counts), CLAIM.md, my family checker, the CNF (triples with A&B=A&C=B&C, including pairwise disjoint triples; brute force confirmed 1400) . Family is uniform r=3 (the bank's uniform-family setting; g(8,3) is the r-uniform maximum, not f(8) over all subsets). The value is exactly the maximum for (n,r)=(8,3): size-12 family exists AND size 13 UNSAT. Symmetry breaking is the only extra assumption and is sound.
